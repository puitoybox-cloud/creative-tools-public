# 創作設定アトリエ

創作作品の非公開設定を、iPad と Mac のブラウザで整理するための HTML/CSS/JavaScript 製アプリです。サーバーやビルド環境は不要で、`index.html` を開くだけで動きます。

## できること

- 複数作品を作成できます（例：ラクリマテイル、ティア・ノヴァ）。
- 作品ごとに次の情報を分けて管理できます。
  - キャラクター
  - 話数メモ
  - 世界観・設定
  - 画像生成プロンプト
- 登録、編集、削除、検索ができます。
- 画像生成プロンプトはコピーできます。
- 入力・編集・削除後に `localStorage` へ自動保存します。
- すべてのデータを JSON で書き出し／復元できます。
- iPad Safari とスマホ幅でも押しやすいように、文字とボタンを大きめにしています。

## ファイル構成

```text
creative-tools-public/
├── index.html   # 画面構造
├── styles.css   # 見た目・iPad/スマホ対応
├── app.js       # 作品管理、CRUD、検索、自動保存、JSONバックアップ
└── README.md    # 使い方
```

## 初心者向け：基本の使い方

1. `index.html` をブラウザで開きます。
2. 「作品管理」で使いたい作品を選びます。
3. 新しい作品を作りたい場合は「新しい作品名」に入力して「作品を追加」を押します。
4. 「キャラクター」「話数メモ」「世界観・設定」「画像プロンプト」のタブを選びます。
5. 左側または上側のフォームに入力し、「保存する」を押します。
6. 登録済みカードが一覧に表示されます。
7. 一覧上部の検索欄で、名前・本文・メモなどから絞り込めます。

## 各タブで管理できる内容

### キャラクター

- 名前
- 役割
- 外見
- 性格
- 口調
- 重要設定
- メモ

### 話数メモ

- 話数
- タイトル
- あらすじ
- 確定設定
- 矛盾チェック用メモ

### 世界観・設定

- 分類
- 設定名
- 内容
- 状態（確定／仮設定）

### 画像生成プロンプト

- 用途
- キャラクター
- プロンプト本文
- ネガティブ指定
- サイズ
- メモ

登録済みカードの「コピー」を押すと、プロンプト情報をまとめてクリップボードへコピーできます。

## 編集・削除

### 編集

1. 登録済みカードの「編集」を押します。
2. 内容がフォームに戻ります。
3. 修正して「変更を保存」を押します。
4. 編集をやめたい場合は「編集をやめる」を押します。

### 削除

- 1件だけ消す場合は、カードの「削除」を押します。
- 開いているタブの中身を全部消す場合は、「このタブを全削除」を押します。
- 作品ごと消す場合は、「選択中の作品を削除」を押します。

削除前には確認ダイアログが出ます。

## 保存について

このアプリは、まずはクラウドを使わず `localStorage` に自動保存します。

- 入力、編集、削除、作品追加、作品切り替えのたびに保存します。
- ページを閉じても、同じブラウザなら内容が残ります。
- サーバーには送信されません。
- iPad の Safari で履歴や Web サイトデータを削除すると、保存内容も消えることがあります。
- 別端末や別ブラウザには自動同期されません。

## iPadでの使い方

1. iPad の Safari で `index.html` または GitHub Pages のURLを開きます。
2. 共有ボタンから「ホーム画面に追加」すると、アプリのように起動しやすくなります。
3. 長文入力が多い場合は、外付けキーボードを使うと編集しやすくなります。
4. Safari の「履歴とWebサイトデータを消去」を行う前に、必ず JSON バックアップを書き出してください。

## JSONバックアップ

### 書き出し

1. 画面右上の「JSONを書き出す」を押します。
2. `creative-settings-YYYY-MM-DD.json` というファイルが保存されます。
3. iPad では「ファイル」アプリ、iCloud Drive、または外部ストレージに保管してください。

### 復元

1. 「JSONを読み込む」を押します。
2. 以前に書き出した JSON ファイルを選びます。
3. 確認ダイアログで OK を押すと、現在の保存内容を置き換えます。
4. 壊れた JSON や形式が違う JSON は読み込まず、エラーを表示します。

> 復元は上書きです。心配な場合は、復元前に現在のデータも JSON で書き出してください。

## ローカルで確認する方法

`index.html` をダブルクリックして開けます。より安定して確認したい場合は、リポジトリのフォルダで次を実行します。

```bash
python3 -m http.server 8000
```

そのあと、ブラウザで `http://localhost:8000` を開きます。

## 将来Firebaseでクラウド保存に移行するための考え方

現在の `app.js` は、画面表示とデータ保存を分けやすいようにしています。

移行時の方針：

1. `loadData()` を Firebase Firestore から読み込む処理に置き換えます。
2. `saveData()` を Firestore へ保存する処理に置き換えます。
3. `activeProject()`、`activeEntries()`、`tabDefinitions`、フォーム描画、一覧描画はそのまま活かせます。
4. 端末間同期が必要な場合は、Firestore のリアルタイムリスナーで `data` を更新して `render()` を呼びます。
5. 非公開利用が前提なので、Firebase Authentication を追加し、ログインした本人だけが読めるセキュリティルールにしてください。

おすすめのデータ構造例：

```text
users/{uid}/appData/main
```

または作品単位で分ける場合：

```text
users/{uid}/projects/{projectId}
users/{uid}/projects/{projectId}/characters/{characterId}
users/{uid}/projects/{projectId}/episodes/{episodeId}
users/{uid}/projects/{projectId}/worlds/{worldId}
users/{uid}/projects/{projectId}/prompts/{promptId}
```

最初は現在の JSON 全体保存に近い `appData/main` 方式が簡単です。データ量が増えたら、作品単位・コレクション単位へ分割してください。
